# Cotejo 1.2.5 (beta)

**Cotejo es el tablero de control para hacer vibe coding profesional. Tus agentes entregan. Tú
compruebas.** Es gratis, para Windows y Linux. Esta versión te deja empezar en cualquier repo sin
vault, le pone versión a tu proyecto y a cada tarea, pule el board para el tema claro y las
ventanas estrechas, y arregla lo que fallaba la primera vez que se usa Cotejo en una máquina sin
git, sin agentes o sin segundo cerebro.

La 1.2.4 se quedó en borrador y no llegó a publicarse: todo lo que traía está aquí.

> [!WARNING]
> **Cotejo 1.2 sigue siendo software en fase beta.** Todavía puede tener fallos o comportarse de
> forma inesperada. Se ofrece «tal cual», sin garantías de ningún tipo, como dice su licencia
> ([`LICENSE`](https://github.com/Rafael088/cotejo/blob/main/LICENSE), cláusula 8). Haz copia de
> tu segundo cerebro antes de probarlo y, si algo falla, cuéntalo en un
> [issue](https://github.com/Rafael088/cotejo/issues).

## Descargar

Cada archivo se descarga con su enlace, o desde la lista **Assets** al final de esta página.

| Sistema | Archivo | Cómo se instala |
|---|---|---|
| Windows 10/11 (64 bits) | [`Cotejo-1.2.5-windows-x64-instalador.exe`](https://github.com/Rafael088/cotejo/releases/download/v1.2.5/Cotejo-1.2.5-windows-x64-instalador.exe) | Doble clic y siguiente. |
| Arch Linux / Omarchy | [`cotejo-1.2.5-1-any.pkg.tar.zst`](https://github.com/Rafael088/cotejo/releases/download/v1.2.5/cotejo-1.2.5-1-any.pkg.tar.zst) | `sudo pacman -U cotejo-1.2.5-1-any.pkg.tar.zst` |
| Otras distribuciones de Linux | [`cotejo-1.2.5-linux.tar.gz`](https://github.com/Rafael088/cotejo/releases/download/v1.2.5/cotejo-1.2.5-linux.tar.gz) | Ver abajo. |

**Si ya tienes la 1.0, la 1.1 o una 1.2 anterior**, instala la 1.2.5 encima igual que la primera vez: tus tareas viven en tu
vault o en tu repo, y el instalador no las toca. `cotejo --version` debe decir `cotejo 1.2.5`.

**Windows.** El instalador no pide administrador: instala Cotejo para tu usuario, lo pone en el
menú Inicio, añade el comando `cotejo` al PATH (para ti y para tus agentes), instala las
tipografías del board y avisa a los agentes que tengas (Claude Code, opencode…). Al terminar
abre el board. Abre una terminal nueva para usar `cotejo`; `cotejo doctor` dice qué falta
configurar. Se desinstala desde *Configuración → Aplicaciones*.

**Linux.**

```sh
tar -xzf cotejo-1.2.5-linux.tar.gz
cd cotejo-1.2.5
./install.sh
```

## Comprobar la descarga

Los SHA-256 de todos los archivos están en
[`SHA256SUMS`](https://github.com/Rafael088/cotejo/releases/download/v1.2.5/SHA256SUMS). En Linux,
con los archivos en la misma carpeta: `sha256sum -c --ignore-missing SHA256SUMS`. En Windows, en
PowerShell: `Get-FileHash Cotejo-1.2.5-windows-x64-instalador.exe`, y compara con su línea.

`Cotejo-1.2.5-fuentes-terceros.tar` trae el código fuente de los componentes LGPL/GPL que
incluye la versión de Windows, los mismos que lleva este instalador. No hace falta para usar
Cotejo.

## Novedades

- **El primer uso, sin tropiezos.** Probado en una cuenta vacía, sin git, sin agentes y sin vault:
  - `cotejo init --repo <carpeta>` deja un primer commit con `.cotejo/`, aunque git no sepa
    todavía quién eres, y `despachar` funciona a la primera. Si el repo no tiene ningún commit,
    `despachar` lo dice antes de tomar la tarea.
  - Sin git instalado, `init` dice primero que falta git.
  - `despachar` ya no deja tareas «Haciéndola» sin nadie detrás: si el agente no está instalado
    no la toma, y si falla (por ejemplo, Claude Code sin sesión iniciada) la devuelve a
    Pendiente con lo que dijo el agente como motivo y sin perder el modelo asignado. El motivo
    de un despacho fallido deja de verse en cuanto alguien la vuelve a tomar.
  - `cotejo config init` deja el repo como fuente, salvo que tengas un vault de Obsidian que
    exista de verdad; `doctor` sugiere `init` y, si encuentra tu vault, `fuentes usar obsidian`.
  - Sin ningún agente de terminal (Claude Code, Codex, Gemini CLI, opencode), `doctor`,
    `modelos`, `plan` y `maestro` lo dicen con claridad, sin dar a entender que hay uno.
  - El instalador reconoce un agente recién instalado que nunca se abrió, y le pone la skill.
  - El board, la primera vez y sin ningún proyecto, explica qué es Cotejo y cómo empezar con dos
    comandos para copiar; **Abrir maestro** se desactiva mientras no haya de dónde leer.
  - `cotejo --board` sin pantalla (por ssh o en una terminal) sale con un mensaje en vez de
    romperse.

- **Cotejo tiene identidad nueva.** El README, la web, la descripción de las skills y el objetivo
  del proyecto cuentan lo mismo: el tablero de control para hacer vibe coding profesional, donde
  tus agentes entregan y tú compruebas. La web tiene ahora su propio dominio,
  [cotejo.dev](https://cotejo.dev), y el instalador baja de ahí.
- **Con cualquier agente.** Una sección nueva en el README y en la web explica cómo usar Cotejo
  con Claude Code, Codex, Gemini CLI, opencode o cualquier agente que hable MCP.
- **Empezar sin vault.** `cotejo init` funciona en una carpeta que no existe o que no tiene git:
  la crea, le hace `git init` y deja `.cotejo/` completo, con el proyecto en la versión 0.1.0. En
  una instalación nueva, el repo es la fuente por defecto: `init` la activa si la que había no
  funciona (y no te cambia una que sí funcione). `cotejo doctor` y la skill de fuentes proponen
  `init` primero.
- **Una skill para empezar.** Los agentes aprenden a abrir un proyecto con Cotejo: `init`, una
  entrevista corta y el primer plan de la 0.1.0, también para un proyecto que viene de Obsidian
  o de Notion.
- **Versiones del proyecto y de cada tarea.** El proyecto sabe cuál es su versión publicada (por
  git) y cuál está en curso. Cada tarea puede pertenecer a una versión con `#vX.Y.Z`;
  `cotejo version` dice qué lleva la en curso y qué se aprobó desde el último tag, y
  `cotejo tareas --version` y `cotejo crear --version` la filtran y la asignan.
- **Las notas del release salen de las tareas aprobadas.** `cotejo release` arma las notas de la
  versión con lo aprobado (en ensayo por defecto; con `--aplicar` las escribe). Nunca etiqueta ni
  publica: eso lo haces tú.
- **Entregar para quien no programa.** `cotejo entregar --resumen` lleva a la tarea un resumen en
  lenguaje llano de lo que se hizo, y el board tiene una vista de revisión que lo muestra para
  que compruebes sin leer código.
- **Un board con más aire.** Columnas más anchas y con aire, banda de proyectos, pie en tres
  zonas a todo el ancho, cartas por columna con ventana de detalle, Finalizada siempre plegada, el
  nombre corto y la versión de cada tarea, y el modelo asignado visible en Haciéndola.
- **Cabe en una ventana estrecha.** A 1430 px caben las cuatro columnas sin desplazarte: se
  estrechan hasta un mínimo cuando la ventana no da. Y el menú de la cabecera se abre entero
  dentro de la ventana.
- **Tema claro legible.** Al cambiar de tema, los diálogos y los avisos del board se ven bien.
- **Arreglos.** La carta de Pendiente solo se abre con el foco si es foco de teclado visible.
