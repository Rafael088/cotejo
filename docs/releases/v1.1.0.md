# Cotejo 1.1.0 (beta)

La 1.0 servía a quien tiene sus tareas en un vault de Obsidian. La 1.1 es para cualquiera que
programa con agentes: las tareas pueden vivir **en el repo**, se entra por **MCP** desde cualquier
cliente, un plan se convierte en tareas sin copiarlas a mano, y lo que entrega un agente se
**revisa de un vistazo** sin que dos agentes se pisen.

> [!WARNING]
> **Cotejo 1.1 sigue siendo software en fase beta.** Todavía puede tener fallos o comportarse de
> forma inesperada. Se ofrece «tal cual», sin garantías de ningún tipo, como dice su licencia
> ([`LICENSE`](https://github.com/Rafael088/cotejo/blob/main/LICENSE), cláusula 8). Haz copia de
> tu segundo cerebro antes de probarlo y, si algo falla, cuéntalo en un
> [issue](https://github.com/Rafael088/cotejo/issues).

## Descargar

Cada archivo se descarga con su enlace, o desde la lista **Assets** al final de esta página.

| Sistema | Archivo | Cómo se instala |
|---|---|---|
| Windows 10/11 (64 bits) | [`Cotejo-1.1.0-windows-x64-instalador.exe`](https://github.com/Rafael088/cotejo/releases/download/v1.1.0/Cotejo-1.1.0-windows-x64-instalador.exe) | Doble clic y siguiente. |
| Arch Linux / Omarchy | [`cotejo-1.1.0-1-any.pkg.tar.zst`](https://github.com/Rafael088/cotejo/releases/download/v1.1.0/cotejo-1.1.0-1-any.pkg.tar.zst) | `sudo pacman -U cotejo-1.1.0-1-any.pkg.tar.zst` |
| Otras distribuciones de Linux | [`cotejo-1.1.0-linux.tar.gz`](https://github.com/Rafael088/cotejo/releases/download/v1.1.0/cotejo-1.1.0-linux.tar.gz) | Ver abajo. |

**Si ya tienes la 1.0**, instala la 1.1 encima igual que la primera vez: tus tareas viven en tu
vault o en tu repo, y el instalador no las toca. `cotejo --version` debe decir `cotejo 1.1.0`.

**Windows.** El instalador no pide administrador: instala Cotejo para tu usuario, lo pone en el
menú Inicio, añade el comando `cotejo` al PATH (para ti y para tus agentes), instala las
tipografías del board y avisa a los agentes que tengas (Claude Code, opencode…). Al terminar
abre el board. Abre una terminal nueva para usar `cotejo`; `cotejo doctor` dice qué falta
configurar. Se desinstala desde *Configuración → Aplicaciones*.

**Linux.**

```sh
tar -xzf cotejo-1.1.0-linux.tar.gz
cd cotejo-1.1.0
./install.sh
```

## Comprobar la descarga

Los SHA-256 de todos los archivos están en
[`SHA256SUMS`](https://github.com/Rafael088/cotejo/releases/download/v1.1.0/SHA256SUMS). En Linux,
con los archivos en la misma carpeta: `sha256sum -c --ignore-missing SHA256SUMS`. En Windows, en
PowerShell: `Get-FileHash Cotejo-1.1.0-windows-x64-instalador.exe`, y compara con su línea.

`Cotejo-1.1.0-fuentes-terceros.tar` trae el código fuente de los componentes LGPL/GPL que
incluye la versión de Windows, los mismos que lleva este instalador. No hace falta para usar
Cotejo.

## Novedades

### Sin vault: las tareas en el repo

- **Fuente repo.** Un repo de git es un proyecto, y sus tareas viven en `.cotejo/tareas.md` con
  la misma línea que en una nota de Obsidian (`- [ ] texto #medio #agente/x ^cotejo-id`). Se
  lee bien en GitHub y en cualquier editor, y no hace falta tener Obsidian.
- **`cotejo init`.** Dentro de un repo, crea `.cotejo/tareas.md` y lo registra en la fuente
  repo; luego `cotejo fuentes usar repo` la activa. Repetirlo no cambia nada, y `cotejo doctor`
  avisa si el repo quedó listo pero estás usando otra fuente.

### Para cualquier cliente: servidor MCP

- **`cotejo mcp`** sirve los mismos verbos de la CLI como tools del Model Context Protocol, por
  stdio y sin dependencias. Se conecta desde Claude Code (`claude mcp add cotejo -- cotejo mcp`),
  opencode o cualquier cliente MCP. Como en la CLI, no hay ninguna tool para dar una tarea por
  hecha: eso sigue siendo tuyo.

### Revisar lo que entrega un agente

- **Evidencia que se puede volver a comprobar.** `entregar` anota, además del texto, la rama, los
  commits y el resumen del diff, y corre él mismo cada `--prueba` (sin shell y con tiempo límite)
  guardando su salida y su código de salida.
- **`cotejo comprobar <id>`** vuelve a correr esas pruebas y dice si el resultado sigue igual.
  Solo lee: no cambia el estado de la tarea.
- **Un worktree por tarea.** Cuando la tarea es de un repo de git, `despachar` le crea su propio
  worktree con una rama `cotejo/<id>`, así dos agentes no se pisan en el mismo repo.
  `cotejo worktrees` lista dónde quedó cada uno y `--limpiar` retira los que sobran, sin borrar
  nunca una rama ni nada sin commitear. `--sin-aislar` vuelve al comportamiento de antes.
  Funciona igual en Windows.
- **Revisión en el board.** La carta de una entrega con evidencia trae tres botones:
  **Comprobar** (lo mismo que `cotejo comprobar`), **Revisar** (el diff de la entrega partido
  por archivo, plegable y con color por línea, o en tu herramienta de diff para cambios grandes)
  y **Aprobar**, que la marca como hecha y te *ofrece* integrar su rama.

### Del plan a las tareas

- **`cotejo importar plan <plan.md> --proyecto X`** convierte las casillas `- [ ]` de un plan (o,
  si no hay, sus encabezados de paso) en tareas, cada una con la dificultad y el modelo que
  propone el enrutador. Es un ensayo por defecto: solo escribe con `--aplicar`, y repetirlo no
  duplica tareas.

### Más pequeño

- **`cotejo tareas` ya no lista las hechas** por defecto; `--todas` las incluye y
  `--estado hecha` muestra solo esas.
